# 비즈니스폼+ 만들기

사용자의 목적에 맞는 폼을 만들고 실제 저장 상태까지 확인한다. 기능 설명 요청이면 설명만, 기획 요청이면 설계안만 작성한다. 폼 제작 요청에 광고 집행, 참가자 연락, 실제 경품 추첨·지급 권한까지 포함된 것으로 해석하지 않는다.

## 시작할 때

1. 대상 광고계정과 요청 작업을 현재 화면에서 확인한다. 기존 폼이면 이름과 ID로 구분한다. 같은 이름만 보고 대상이라고 단정하지 않는다.
2. 목적, 테스트/실운영, 행사명, 참여 대상, 연락 수단, 보유 기간, 최종 저장 여부를 대화에서 추출한다. 행사 일정·경품·당첨 인원·발표 방법·위탁사·채널·URL은 필요한 경우에만 확인한다. 값이 없는 초안은 미정이라고 표시하되 실제 저장값에 가짜 사업자·연락처·일정·경품을 넣지 않는다.
   동의문은 사용자가 진행할 이벤트와 개인정보 사용 목적에 맞게 작성한다. 이벤트가 대화에서 확인되지 않으면 먼저 어떤 이벤트인지 묻고, 수집 항목·주체·보유 및 처리 계획 중 필요한 빈값을 확인한다. 세미나를 일반 기본값으로 쓰지 않는다. 행사 내용이 없는 순수 기능 테스트 요청에만 세미나 테스트 예시를 사용하며 이 가정을 알린다. 사용자가 다른 테스트 이벤트를 지정하면 그 내용을 우선한다.
3. 광고계정의 사업자와 실제 수집 주체가 맞는지 확인한다. 권한 보유/위임 확인은 사용자 진술을 근거로 한다. 로그인이나 마스터 표시만으로 광고주의 위임을 추정하지 않는다. 같은 사용자·광고계정·작업에서 이미 확인받은 권한을 다시 묻지 않고 해당 진술에 근거해 권한 확인 상자를 체크한다. 등록 화면 접근 자체만으로 모든 계정의 권한·위임을 보장한다고 설명하지 않는다.
4. 기본은 Codex native Computer Use의 **Chrome 확장 프로그램을 통한 특정 탭 제어**다. 데스크톱의 Chrome 앱 전체 제어와 구분한다. 사용자 지정 브라우저·탭이 우선하며, 사용 가능한 도구의 문서를 읽어 연결을 초기화한 뒤 기존 작업 탭을 지정한다. 연결·탐색·권한 문제는 [verification.md](references/verification.md)의 ‘Chrome 작업 탭 연결’을 따른다. Chrome을 사용할 수 없다면 확인된 장애와 대안의 차이를 설명한다. 임의로 Aside·ego-browser·인앱 브라우저로 바꾸지 않는다.

## 실행

- 카카오모먼트 → 광고자산 관리 → 비즈니스폼+ 관리에서 시작한다. 구 비즈니스폼 연동 관리와 구분한다.
- 현재 접근성 트리/DOM/스크린샷으로 버튼과 입력란을 찾는다. 다른 세션의 좌표·요소 번호·광고계정 ID를 재사용하지 않는다. 동작 후 새 상태로 다음 판단을 한다.
- 지정한 작업 탭의 핸들을 유지한다. 사용자가 다른 Chrome 창을 쓰더라도 활성 창으로 입력 대상을 다시 고르지 않는다. 일반 본문이 비어 있으면 Shadow DOM과 iframe을 포함한 snapshot을 확인한다. 도구 문서에 없는 초기화 코드나 AppleScript·System Events 경로를 만들어 쓰지 않는다.
- 중앙 참여자 미리보기와 우측 설정 입력란을 구분한다. 미리보기의 개인정보 동의 버튼을 운영자 설정으로 착각하지 않는다.
- 선택 기능은 목적에 맞게 켜거나 끈다. 기본값도 확인한다. 특히 채널 상담의 기본 ON, 예시 연락처, 자동 생성 문항을 그대로 저장하지 않는다.
- 정보를 입력하면서 글자수·문항수·보기수·필수 응답·선택 동의·모바일 표시를 확인한다. 실제 제한과 참고자료가 다르면 화면에서 확인한 제한을 적용하고 차이를 보고한다.
- 권한·연락처 등 필수 사실이 없으면 해당 단계만 보류하고 나머지 초안은 완성한다. 순수 테스트 초안에서 보유 기간만 미확정이면 임시 저장용 미정 표시를 사용할 수 있다([verification.md](references/verification.md)). 이는 실제 운영 기간의 확정이 아니며 작성 완료·실제 수집 전에 확정한다. 권한 확인 상자를 근거 없이 체크하거나 비활성 저장 버튼을 우회하지 않는다.
- 임시 저장은 수정 가능한 초안이며, 최종 저장 후에는 내용 수정이 불가능하다. 사용자가 완성된 폼 제작을 요청했고 내용과 권한이 확정되면 완료 저장까지 진행한다. 검토용·테스트용 제작은 임시 저장과 재진입 확인까지 기본으로 마치되, **‘저장하지 말 것’은 임시 저장도 하지 않는다는 뜻**이다. ‘최종 저장만 하지 말 것’은 임시 저장 여부를 기존 요청과 맥락에서 구분한다. 저장 직전에 완성 내용을 검증하고 결과 요약을 전달한다. 미저장 검토 요청이면 편집기를 유지하고 초안을 버리는 닫기·재로드·이동을 하지 않는다.
- 실제 화면에서 약관 수락·영구 삭제·민감정보 접근 확대·암호 변경 등 확인/직접 조작이 필요한 동작은 실행 환경의 정책을 따른다. 일반 제작과 읽기만으로 매번 별도의 승인 절차를 만들지 않는다.

## 완료 증거

클릭 성공과 저장 성공을 구분한다. 임시 저장은 편집기의 마지막 저장 표시와 목록 조회로 이름·폼 ID·상태를 확인한 뒤 같은 폼을 다시 열어 주요 내용과 수정 가능한 필드를 확인한다([verification.md](references/verification.md)). 목록이 갱신되지 않으면 조회를 실행한다. 작성 완료는 실제 성공 화면 또는 목록 상태로 확인한다. 저장 성공이 모호하면 조회를 먼저 해 중복 생성을 막는다. 재진입하지 못했으면 저장 확인과 재진입 미확인을 구분해 보고한다.

결과는 폼 이름, 확인된 ID, 임시 저장/작성 완료/미저장 상태, 설정 요약, 확인된 랜딩 URL, 남은 제약으로 짧게 보고한다. ID・URL이 아직 생성되지 않았으면 미확인으로 표시한다. 미저장 작업은 임시·완료 저장을 실행했는지 각각 명시하고, 다음 검토를 위해 도구가 지원하면 작업 탭을 handoff로 유지한다. 브라우저에서 변경을 했다면 개인정보가 드러나지 않는 결과 화면을 증거로 남기고 **저장된 이미지 자체를 시각 검증**한다. 계정 화면·응답 파일·토큰·암호를 공개 저장소나 공유 예시에 넣지 않는다.
