# 검증·문제 해결

## 확인 범위

2026-10-05에 공식 소개/제작/관리/API 문서를 읽고 Chrome의 실제 관리자 화면을 점검했다.

직접 관찰: 목록과 작성 완료 상태, 상세 설정, 랜딩 URL, 권한 설정 팝업, 알림 일정 팝업, 보고서의 암호 미설정 안내, 암호 입력 팝업, 변경 이력, 빈 제작 편집기, 제목·답변 수정 제한, 시작 페이지, 객관식 문항, 동의문 확장 옵션, 완료 페이지.

문서 기준이며 실행 검증하지 않은 항목: 모든 문항 유형의 실제 제출, 계층형 엑셀 업로드, 이미지 업로드, 실제 채널 추가/상담 전송, 기타동의 최종 저장, 보고서 다운로드/해제, 권한 변경, 알림 발송, 삭제, API 인증/조회, 광고 소재 연결/집행. 이 범위를 실행 성공으로 소개하지 않는다.

2026-10-06 [실사용 피드백 #1](https://github.com/rod0826/kakao-bizformplus-skill/issues/1)에 따라 아래 제어·탐색 지침을 보완했다. 지정된 탭의 iframe에 미저장 초안을 입력했다는 사용자 보고를 근거로 하며, 이번 지침 업데이트 자체가 저장·응답 제출·다른 창 동시 사용을 새로 실행 검증한 것은 아니다.

## Chrome 작업 탭 연결

1. 현재 세션에서 제공되는 native Computer Use 도구와 해당 브라우저 문서를 확인한다. 도구의 발견·초기화와 Chrome 확장 프로그램 연결을 확인하기 전에 기능이 없다고 단정하지 않는다. 도구명·패키지·API는 환경별로 달라질 수 있으므로 다른 노트북의 초기화 코드를 복사하지 않는다.
2. 사용자에게 지정된 탭이 있으면 문서에 안내된 탭 선택 방법을 사용한다. 기존 작업 탭을 찾는 환경에서는 `openTabs()` 목록의 URL·제목으로 대상을 확인하고 반환된 항목을 `claimTab()`으로 지정한다. `cua.getTab(...)`처럼 탭을 직접 지정하는 인터페이스가 제공되면 그 문서를 따른다. 이 이름들이 모든 환경에 존재한다고 가정하지 않는다.
3. 작업 탭의 핸들을 유지하고 현재 URL·편집 내용을 확인한 뒤 입력한다. 활성 Chrome 창이나 `getApp("Google Chrome")`의 결과를 특정 탭과 같은 것으로 취급하지 않는다. 끊긴 핸들은 같은 연결의 탭 목록에서 원래 대상을 다시 확인한다. 기존 초안이 있는 탭을 새 탭·새 폼으로 대체하거나 재로드하지 않는다.
4. 확장 프로그램 연결이 실패하면 반환된 연결 상태와 안내를 근거로 필요한 조치만 설명한다. **Apple Events의 JavaScript 허용은 Chrome 확장 프로그램의 공통 필수 조건으로 안내하지 않는다.** AppleScript 오류는 해당 경로의 오류로 구분한다. 설정·권한 변경은 실제 사용하는 제어 경로에서 필요함이 확인된 경우에만 환경 정책에 따라 처리한다.
5. 탭 제어 대신 데스크톱 앱 제어가 필요한 경우에는 탭을 지정하는 방식과 달리 전면 창·포커스·키보드·마우스에 영향을 줄 수 있음을 먼저 설명하고 사용자 지정 경로를 존중한다. AppleScript·System Events·`@oai/sky`를 임의로 불러와 전환하지 않는다. 사용할 수 있는 도구 문서와 허용된 경로를 따른다.

사용자 조작 때문에 중단됐다는 응답이 오면 확인된 메시지 범위만 보고한다. 정책 변경이나 모든 Chrome 창의 입력 감지가 원인이라고 추정하지 않는다. 최신 상태를 조회해 원래 작업 탭·URL·초안을 다시 확인한 뒤 재개한다. 충돌이 반복되면 입력을 멈추고 작업 탭을 보존한다. 다른 창에서 입력해 복구하려고 하지 않는다.

## Shadow DOM·iframe 편집기 탐색

- 일반 `document.body.innerText`가 비어 있거나 목록만 보여도 로딩 실패·폼 부재로 판정하지 않는다. 현재 탭의 접근성 트리 또는 Shadow DOM·iframe을 포함하는 DOM snapshot을 먼저 확인한다.
- snapshot에서 편집기와 프레임을 식별하고, 도구가 제공하는 frame locator로 해당 프레임의 설정 필드에 접근한다. 프레임 selector는 현재 관찰에서 가져오며 다른 세션의 값을 재사용하지 않는다. 최상위 페이지의 locator가 iframe 내부까지 자동으로 찾는다고 가정하지 않는다.
- 별도 출처 iframe을 최상위 `evaluate`로 읽으려 하지 않는다. 프레임 탐색이 지원되지 않으면 해당 도구의 접근성·스크린샷 경로로 확인한다. 중앙 미리보기와 우측 운영자 설정을 구분한다.
- 입력 뒤 동일 작업 탭의 설정값·미리보기를 확인한다. 다른 창을 보게 됐거나 대상이 모호하면 추가 입력 전에 작업 탭을 다시 지정한다.

## 미저장 초안과 결과 캡처

‘저장하지 않음’, ‘임시 저장’, ‘작성 완료’를 구분해 요청에 맞게 종료한다. 미저장 입력을 저장 성공으로 보고하지 않는다. 임시 저장과 완료 저장의 실행 여부, 남은 필수 사실, 초안이 열린 탭을 알려준다. 사용자의 검토용 미저장 초안은 닫거나 이동해 버리지 않으며, 지원되는 handoff 표시로 유지한다. 별도로 만든 촬영용 임시 예시를 정리하는 것과 구분한다.

캡처 API에 편집기 영역을 지정했더라도 결과가 그 범위라고 가정하지 않는다. 반환·저장된 이미지를 직접 열어 아래를 확인한 뒤 사용자에게 제시하거나 공개한다.

- 현재 편집기와 설명하려는 단계가 실제로 보이며, iframe 대신 뒤쪽 목록만 캡처되지 않았다.
- 계정 헤더·이메일·광고계정 ID·사업자 정보·실제 응답·연락처가 포함되지 않았다. URL 표시줄도 확인한다.
- 잘라내기가 필요하면 실제 이미지의 좌표를 기준으로 처리하고 결과 파일을 다시 본다. 개인정보를 안전하게 제외할 수 없으면 공개하지 않는다.

## 다른 Chrome 창 사용 회귀 확인

동시 사용을 시험할 때는 사용자가 허용한 테스트 초안과 지정 탭에서만 진행한다. 사용자에게 다른 Chrome 창을 사용해 달라고 한 뒤 같은 작업 탭 핸들로 허용된 필드 하나를 입력하고 값·URL·초안 유지를 확인한다. 사용자 작업 창의 내용을 시험 목적으로 읽거나 변경하지 않는다. 중단 응답이 나오면 입력을 멈추고 위 연결 복구 절차를 따른다. 이 시험의 성공·실패와 사용한 경로를 기록하되 모든 환경에서 동시 사용이 가능하다고 일반화하지 않는다. 시험하지 않았다면 미검증이라고 명시한다.

## 저장 전

- 대상 계정·사업자·수집 주체·권한 진술이 일치한다.
- 문항 유형·질문·보기·필수·순서가 기획과 맞는다.
- 자동 생성된 예시 문항·연락처·채널 기본값이 남지 않는다.
- 목적·보유 기간·처리 업체·동의 필수/선택이 실제 운영과 맞는다.
- 참여 안내, 완료 연락 안내, 상담/추가 URL/공유 설정이 맞는다.
- 테스트 표시·실제 경품 지급 여부가 모든 안내에서 일치한다.
- UI가 요구하는 모든 필수값과 글자수 조건이 충족된다.
- 요청된 종료 상태가 임시 저장인지 완료인지 확정된다.

## 저장이 막힐 때

저장 버튼이 비활성이면 좌측 오류 표시와 해당 페이지의 검증 메시지를 먼저 확인한다. 권한 확인, 정보 수집 선택, 목적/기간, 제목, 기본 ON인 채널 상담의 미선택 채널을 우선 점검한다. 비활성 버튼을 DOM 조작으로 활성화하지 않는다.

저장 후 성공이 불명확하면 목록에서 이름·ID·상태를 조회한다. 확인 전에 새 폼을 다시 만들지 않는다. 완료 후 변경 요청은 새 폼으로 구현하고 기존 연결 교체 여부는 요청 범위에서 결정한다.

## 화면·정책이 달라질 때

기능별 공식 링크의 해당 부분과 현재 화면 도움말을 다시 읽는다. 캐시된 제한을 영구 규칙으로 취급하지 않는다. 버튼명·제한·지원 상태의 차이를 기록하고 필요한 부분만 스킬 자료를 갱신한다. 공식 가이드 링크를 사용자가 매번 제공할 필요는 없다.

브라우저 연결이 끊기면 기존 작업의 저장 여부부터 확인한다. 로그인·CAPTCHA·권한 제한 때문에 진행할 수 없으면 가능한 설계와 입력을 마친 뒤 구체적 장애와 사용자가 해야 할 동작을 알린다.
