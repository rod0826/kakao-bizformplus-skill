# 검증·문제 해결

## 확인 범위

2026-10-05에 공식 소개/제작/관리/API 문서를 읽고 Chrome의 실제 관리자 화면을 점검했다.

직접 관찰: 목록과 작성 완료 상태, 상세 설정, 랜딩 URL, 권한 설정 팝업, 알림 일정 팝업, 보고서의 암호 미설정 안내, 암호 입력 팝업, 변경 이력, 빈 제작 편집기, 제목·답변 수정 제한, 시작 페이지, 객관식 문항, 동의문 확장 옵션, 완료 페이지.

문서 기준이며 실행 검증하지 않은 항목: 모든 문항 유형의 실제 제출, 계층형 엑셀 업로드, 이미지 업로드, 실제 채널 추가/상담 전송, 기타동의 최종 저장, 보고서 다운로드/해제, 권한 변경, 알림 발송, 삭제, API 인증/조회, 광고 소재 연결/집행. 이 범위를 실행 성공으로 소개하지 않는다.

## 저장 전

- 대상 계정·사업자·수집 주체·권한 진술이 일치한다.
- 문항 유형·질문·보기·필수·순서가 기획과 맞는다.
- 자동 생성된 예시 문항·연락처·채널 기본값이 남지 않는다.
- 목적·보유 기간·처리 업체·동의 필수/선택이 실제 운영과 맞는다.
- 참여 안내, 완료 연락 안내, 상담/추가 URL/공유 설정이 맞는다.
- 테스트 표시·실제 경품 지급 여부가 모든 안내에서 일치한다.
- UI가 요구하는 모든 필수값과 글자수 조건이 충족된다.
- 요청된 종료 상태가 임시 저장인지 완료인지 확정된다.

## 저장이 막힐 때

저장 버튼이 비활성이면 좌측 오류 표시와 해당 페이지의 검증 메시지를 먼저 확인한다. 권한 확인, 정보 수집 선택, 목적/기간, 제목, 기본 ON인 채널 상담의 미선택 채널을 우선 점검한다. 비활성 버튼을 DOM 조작으로 활성화하지 않는다.

저장 후 성공이 불명확하면 목록에서 이름·ID·상태를 조회한다. 확인 전에 새 폼을 다시 만들지 않는다. 완료 후 변경 요청은 새 폼으로 구현하고 기존 연결 교체 여부는 요청 범위에서 결정한다.

## 화면·정책이 달라질 때

기능별 공식 링크의 해당 부분과 현재 화면 도움말을 다시 읽는다. 캐시된 제한을 영구 규칙으로 취급하지 않는다. 버튼명·제한·지원 상태의 차이를 기록하고 필요한 부분만 스킬 자료를 갱신한다. 공식 가이드 링크를 사용자가 매번 제공할 필요는 없다.

브라우저 연결이 끊기면 기존 작업의 저장 여부부터 확인한다. 로그인·CAPTCHA·권한 제한 때문에 진행할 수 없으면 가능한 설계와 입력을 마친 뒤 구체적 장애와 사용자가 해야 할 동작을 알린다.
