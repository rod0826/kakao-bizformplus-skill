# 세미나 후기·추첨 참여 템플릿

이는 과거 대화의 목적을 재구성한 독자 작성 예시다. 실제 저장된 폼 원문을 복제한 것은 아니다.

**사용 조건:** 사용자가 행사 내용 없이 순수 기능 테스트용 폼을 요청한 경우에만 이 세미나 테스트 예시를 기본으로 제안한다. 세미나를 실운영의 기본 이벤트로 가정하지 않는다. 사용자가 실제 세미나 후기를 요청한 경우에는 해당 행사 정보를 받아 구조를 참고할 수 있다. 다른 이벤트를 지정한 테스트 요청은 그 이벤트에 맞게 작성한다. 동의문은 [이벤트별 초안 절차](consent-drafting.md)를 따른다.

## 테스트 예시

- 관리 이름: `테스트 참여형광고 세미나 후기`
- 이벤트 제목: `테스트 세미나 후기`
- 시작 제목: `참여형광고 세미나 후기를 들려주세요`
- 시작 본문: `세미나에서 도움이 된 내용과 개선할 점을 알려주세요. 이 폼은 기능 확인을 위한 테스트입니다. 추첨 참여 문항은 화면 테스트용이며 실제 추첨이나 경품 지급은 진행하지 않습니다. 실제 개인정보 입력은 피해 주세요.`

|순서|유형|질문|필수|보기/설명|
|---|---|---|---|---|
|1|단일|세미나에 얼마나 만족하셨나요?|예|매우 만족 / 만족 / 보통 / 불만족 / 매우 불만족|
|2|복수|가장 도움이 된 내용은 무엇인가요?|예|참여형광고 소개 / 비즈니스폼 제작 / 실무 운영 사례 / 성과 분석 / 기타|
|3|서술|세미나 참여 후기를 남겨주세요|예|개인정보를 적지 말아주세요|
|4|서술|개선할 점을 알려주세요|아니오|추가로 듣고 싶은 주제도 가능합니다|
|5|단일|추첨 참여 화면을 테스트할까요?|예|참여 화면 테스트 / 참여하지 않음|

정보 수집: 전화번호만 선택하는 예시. 플랫폼의 연락처 필수 수집 구조를 설명하고 실제 참여를 유도하지 않는다. 연락처 없이 저장 가능한 것으로 안내하지 않는다.

수집 목적 예시: `세미나 후기 설문 기능 테스트`

보유 기간 예시: `테스트 종료 후 30일 이내 파기`

보유 기간이 미확정인 순수 테스트 초안의 임시 저장은 [검증 절차](verification.md)의 미정 표시 예외를 따른다. 실제 수집 전에 운영 기간을 확정한다.

30일은 이 예시의 운영 선택이다. 실제 테스트 종료일과 파기 계획을 확인하고 적용한다. 모든 폼의 고정 기본값으로 쓰지 않는다. 위탁/제공/국외 이전은 실제 처리 계획에 따라 설정한다.

완료 안내: 전화번호를 공개하기 어렵다면 UI의 텍스트 유형을 사용해 `테스트용으로 별도 연락하지 않습니다`처럼 표시한다. 완료 연락 텍스트는 20자 제한을 확인한다. 이 유형은 전화번호 표시 영역만 바꾸고 주변 연락·시간 안내가 남을 수 있어 미리보기에서 충돌 여부를 확인하고 제약을 보고한다. 실제 상담이 없으면 채널 상담을 끈다. 추가 액션·공유는 요청된 경우에만 설정한다.

## 실운영으로 전환

다음 정보를 확정한 뒤 테스트 표시와 문구를 실운영 내용으로 바꾼다: 행사/광고주, 대상, 시작·마감 시각, 경품, 당첨 인원, 선정 기준, 발표일·방법, 지급 수단, 연락 담당, 개인정보 처리 주체·위탁/제공/이전·보유 기간.

문항5를 `추첨 이벤트에 참여하시겠어요?`와 `참여합니다 / 참여하지 않습니다`로 변경한다. 참여 문항과 개인정보 동의, 채널 추가, 마케팅 동의를 구분한다. 후기 작성만 요청받았는데 마케팅 동의를 추가하지 않는다.

시작 안내에는 확정된 경품·인원·일정·선정 방법을 평이하게 적는다. 확정되지 않은 조건은 실제 폼 저장 전에 확인한다. 참여하지 않는 사람도 연락처를 수집하게 되는지 점검한다. 조건부 수집을 지원한다고 추정하지 않는다.

폼 제작은 추첨 실행이나 사은품 구매·지급이 아니다. 이 스킬은 추첨 참여 의사 수집과 안내 설계까지 지원한다. 실제 추첨·지급은 별도 요청과 해당 실행 환경의 정책에 따른다.

## 다른 목적에 적용

상담 신청은 관심 분야(단일/계층), 상담 희망 내용(서술), 희망 날짜(날짜), 인원·수량(숫자) 중 필요한 문항만 사용한다. 참석 신청은 행사명·일정·참석 조건·확인 연락 방법을 먼저 명시한다. 상품 선택에는 계층형 데이터와 최신 엑셀 샘플을 사용한다. 설문이 필요 없는 단순 리드 수집이라면 문항을 억지로 추가하지 않는다.
